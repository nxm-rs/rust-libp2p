# Interop tests implementation

This folder defines the implementation for the interop tests.

# Running this test locally

You can run this test locally by having a local Redis instance and by having
another peer that this test can dial or listen for. For example to test that we
can dial/listen for ourselves we can do the following:

1. Start redis (needed by the tests): `docker run --rm -p 6379:6379 redis:7-alpine`
2. In one terminal run the dialer: `RUST_LOG=debug redis_addr=localhost:6379 ip="0.0.0.0" transport=tcp security=noise muxer=yamux is_dialer="true" cargo run --bin native_ping`
3. In another terminal, run the listener: `RUST_LOG=debug redis_addr=localhost:6379 ip="0.0.0.0" transport=tcp security=noise muxer=yamux is_dialer="false" cargo run --bin native_ping`

If testing `transport=quic-v1`, then remove `security` and `muxer` variables from command line, because QUIC protocol comes with its own encryption and multiplexing.

To test the interop with other versions do something similar, except replace one
of these nodes with the other version's interop test.

# Running this test with webtransport dialer in browser

To run the webtransport test from within the browser, you'll need the
`chromedriver` in your `$PATH`, compatible with your Chrome browser.
Firefox is not yet supported as it doesn't support all required features yet
(in v114 there is no support for certhashes).

1. Build the wasm package: `wasm-pack build --target web`
2. Run the dialer: `redis_addr=127.0.0.1:6379 ip=0.0.0.0 transport=webtransport is_dialer=true cargo run --bin wasm_ping`

# Running this test with webrtc-direct

To run the webrtc-direct test, you'll need the `chromedriver` in your `$PATH`, compatible with your Chrome browser.

1. Start redis: `docker run --rm -p 6379:6379 redis:7-alpine`.
2. Build the wasm package: `wasm-pack build --target web`
3. With the webrtc-direct listener `RUST_LOG=debug,webrtc=off,webrtc_sctp=off redis_addr="127.0.0.1:6379" ip="0.0.0.0" transport=webrtc-direct is_dialer="false" cargo run --bin native_ping`
4. Run the webrtc-direct dialer: `RUST_LOG=debug,hyper=off redis_addr="127.0.0.1:6379" ip="0.0.0.0" transport=webrtc-direct is_dialer=true cargo run --bin wasm_ping`

# Running the private-to-private `/webrtc` matrix

`transport=webrtc` runs the private-to-private WebRTC transport: the listener obtains a
reservation on a Circuit Relay v2 node, advertises a
`<relay>/p2p-circuit/webrtc/p2p/<listener-peer-id>` multiaddr via redis, and the dialer
runs the `/webrtc-signaling/0.0.1` exchange over the relayed connection before pinging
over the resulting direct connection. The ping is only counted on the direct connection,
never on the relayed one.

The relay is spawned automatically by the listener side (in `native_ping` itself, or in
the native `wasm_ping` wrapper for a browser listener) and listens on a websocket
multiaddr on the configured `ip`. To use an external relay instead, set
`relay_addr=<multiaddr ending in /p2p/<relay-peer-id>>`. For native peers an optional
`ice_server=stun:<host>:<port>` adds a STUN server to the ICE agent.

The in-fork matrix is native/browser on each side, all four cells over the same
harness. Prerequisites: redis, and for browser cells `chromedriver` in `$PATH` plus
`wasm-pack build --target web` beforehand.

- native listener: `redis_addr=127.0.0.1:6379 ip=127.0.0.1 transport=webrtc is_dialer=false cargo run --bin native_ping`
- native dialer: `redis_addr=127.0.0.1:6379 ip=127.0.0.1 transport=webrtc is_dialer=true cargo run --bin native_ping`
- browser listener: `redis_addr=127.0.0.1:6379 ip=127.0.0.1 transport=webrtc is_dialer=false cargo run --bin wasm_ping`
- browser dialer: `redis_addr=127.0.0.1:6379 ip=127.0.0.1 transport=webrtc is_dialer=true cargo run --bin wasm_ping`

Combine one listener and one dialer per run against a fresh redis. For the
browser-to-browser cell the two `wasm_ping` instances must not collide, so give the
second one `bind_addr=127.0.0.1:8081 chromedriver_port=45783`. Use a stock Chromium
or Chrome build: ICE has been observed never to complete in ungoogled-chromium.

The native-to-native cell is also wired up as a cargo test so the whole flow can run
without containers: `cargo test -p interop-tests --test webrtc -- --ignored` (it is
ignored by default because it needs a fresh redis on `127.0.0.1:6379`).

## Cross-implementation conformance

Cross-implementation `/webrtc` runs are generated by
[libp2p/test-plans](https://github.com/libp2p/test-plans) from
`native-ping-webrtc-version.json` and `chromium-ping-webrtc-version.json`, which
declare only the `webrtc` transport. Pairings cover every implementation that lists
`webrtc` (the js-libp2p browser flavours at the time of writing), in both dial
directions, plus the same-flavour self pairs. The `webrtc-interop.yml` workflow runs
this matrix on manual dispatch; locally, follow the Compose instructions below with
`--extra-version=$RUST_LIBP2P/interop-tests/native-ping-webrtc-version.json` (or the
chromium variant) and `--name-filter="rust-libp2p-head"`.

Conformance surface exercised against the reference implementation: multiaddr parsing
of `<relay>/p2p-circuit/webrtc/p2p/<peer-id>`, the protobuf framing and message flow of
`/webrtc-signaling/0.0.1` (offer, answer, trickled ICE candidates), SDP and certificate
fingerprint handling, and ICE establishment of the direct connection.

## STUN and relay assumptions

- Every `/webrtc` listener needs a Circuit Relay v2 reservation; the relay is part of
  the advertised multiaddr and must accept reservations from the listener and circuits
  from the dialer. The harness relay uses default `libp2p-relay` limits, which are
  ample for a ping exchange but not for long-lived transfers.
- The harness relay listens on plain websockets so both native peers and browsers can
  reach it. Browsers cannot host a relay, so a browser listener relies on the native
  `wasm_ping` wrapper (or an external relay) to provide one.
- No STUN or TURN server is assumed. All peers in the matrix share a network
  (localhost or a compose network), so ICE succeeds with host candidates alone.
  Across real NATs a STUN server is required for server-reflexive candidates
  (`ice_server` for native peers; browsers need it passed to the transport
  configuration), and peers behind address-dependent NATs need a permanent relay
  fallback since TURN is not used.

# Running all interop tests locally with Compose

To run this test against all released libp2p versions you'll need to have the
[libp2p/test-plans](https://github.com/libp2p/test-plans) checked out. Then do
the following (from the root directory of this repository):

1. Build the image: `docker build -t rust-libp2p-head . -f interop-tests/Dockerfile`.
2. Build the images for all released versions in `libp2p/test-plans`: `(cd <path to >/libp2p/test-plans/multidim-interop/ && make)`.
3. Run the test:
```
RUST_LIBP2P="$PWD"; (cd <path to >/libp2p/test-plans/multidim-interop/ && npm run test -- --extra-version=$RUST_LIBP2P/interop-tests/ping-version.json --name-filter="rust-libp2p-head")
```
